# Settings UI Polish Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for the single integrated UI task, followed by spec and quality review. Preserve the approved order below.

**Goal:** Make Kawa's existing settings UI compact, readable, and clearly interactive without changing input-source or shortcut behavior.

**Architecture:** Retain AppKit, the storyboard/controller connections, and MASShortcut's capture/validation/accessibility behavior. Apply native layout, semantic colors, and presentation-only styling. Fit the window to the selected tab and a bounded number of list rows; longer catalogs scroll.

## Task 1: Integrated UI improvements, in sequence

**Files:** `kawa/MainWindowController.swift`, `ShortcutViewController.swift`, `ShortcutCellView.swift`, `PreferencesViewController.swift`, `kawa/en.lproj/Main.storyboard`; add focused AppKit view helpers/project references only if needed. Bump `Info.plist` to 1.2.0 (4). Do not modify switching, storage, registration, catalog, or notification authorization logic.

- [ ] 1. Use a compact approximately 520-point-wide native window with 20-point content margins. Size it to the active tab/content, cap visible rows (around 8) and scroll larger lists. Avoid resize loops, clipping, and resetting an active recorder on unchanged catalog refresh.
- [ ] 2. Increase row height to roughly 40–44 points; align 18–20-point icons, readable 13-point names, and the shortcut column. Give names more space, retain full-name tooltips, and use subtle semantic row separators/backgrounds. Missing icons should have a consistent native fallback. Preserve all dynamic rows and mode distinctions.
- [ ] 3. Replace broad inactive-looking gray controls with compact lightly bordered shortcut buttons. Distinguish empty, assigned, recording, focused, and disabled states using semantic colors. Show a clear recording prompt and stable clear/cancel affordance. Keep MASShortcut keyboard capture, duplicate/OS validation, clearing, Escape cancellation, and accessibility semantics; use supported styling/subclass hooks rather than replacing keyboard event handling or changing the dependency.
- [ ] 4. Rename System Settings to General. Keep Shortcuts as the other tab, with consistent native tab styling. Arrange the existing notification preference and Quit button as a compact general pane.
- [ ] 5. Show small secondary explanatory text, and target-associated error text near the relevant row when feasible. Reserve global status for app-wide/empty-catalog messages. Collapse unused status space, wrap longer messages, and preserve notification status visibility. Do not request notification permission during styling/testing.
- [ ] Build, run the existing XCTest suite, self-review, and commit the UI implementation. No new unit tests solely to assert visual constants or mirror layout code; add meaningful regression coverage only if layout support introduces nontrivial behavior.
- [ ] Complete independent spec review, then code-quality review; fix important findings before delivery.
